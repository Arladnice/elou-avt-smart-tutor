# Публикация через Caddy (боевой хост)

На сервере порты `80` и `443` занимает Caddy — общий фронт-прокси для нескольких
проектов. Он терминирует TLS, сам выпускает и продлевает сертификат Let's Encrypt
и раскидывает запросы по имени домена. Стек тренажёра поэтому **не занимает порт 80**,
а публикует интерфейс на `8080` и стоит за прокси.

## Почему без него не работал HTTPS

Caddy принимает соединение на `443`, но если для запрошенного домена (SNI) у него
нет site-блока, сертификата он предъявить не может и рвёт соединение сразу:

```
no peer certificate available
SSL handshake has read 0 bytes and written 1555 bytes
```

Снаружи это выглядит как «сайт не работает», хотя по HTTP всё отдаётся. Лечится
одним блоком в конфигурации.

## Настройка

Найти Caddyfile и сеть контейнера:

```bash
docker inspect beresta-caddy-1 --format '{{json .Mounts}}{{"\n"}}{{json .NetworkSettings.Networks}}'
```

Добавить в Caddyfile блок:

```caddyfile
tutor.kluknulo.ru {
    # Caddy живёт в контейнере, поэтому 127.0.0.1 для него — он сам.
    # Адрес хоста со стороны контейнера — шлюз его docker-сети.
    # Узнать: docker inspect beresta-caddy-1 -f '{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}'
    reverse_proxy 172.17.0.1:8080
}
```

Применить без перезапуска:

```bash
docker exec beresta-caddy-1 caddy reload --config /etc/caddy/Caddyfile
```

Сертификат Caddy выпустит сам при первом обращении по HTTPS — отдельных действий
не нужно, но домен обязан резолвиться на этот хост заранее.

## Проверка

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://tutor.kluknulo.ru/
curl -sS https://tutor.kluknulo.ru/api/health
```

Ожидается `200` и `{"status":"ok"}`.

WebSocket (`/ws`) отдельной настройки не требует: `reverse_proxy` в Caddy v2
проксирует upgrade-соединения прозрачно. Для тренажёра это критично — вся
телеметрия идёт именно через WebSocket.

## Осталось закрыть

Порт `8080` опубликован на всех интерфейсах, то есть приложение доступно и напрямую,
в обход HTTPS. Если это нежелательно — закрыть его снаружи файрволом, оставив доступ
только с самого хоста:

```bash
ufw deny 8080/tcp
```

Полностью снять публикацию (`ports` → `expose`) и ходить по имени контейнера можно
только после того, как Caddy и стек тренажёра окажутся в одной docker-сети.
