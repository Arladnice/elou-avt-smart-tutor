# Требования и границы MVP

## Назначение

КТК ЭЛОУ-АВТ помогает инструктору проводить учебные сессии операторов ЭЛОУ-АВТ. Система моделирует технологическую ситуацию, записывает действия и формирует материал для разбора. Она не управляет реальной установкой и не принимает юридически значимое решение о допуске сотрудника.

## Реализовано в MVP

| ID | Требование | Подтверждение |
|---|---|---|
| FR-01 | Вход оператора и инструктора | REST login, JWT, разные экраны |
| FR-02 | Серверная ролевая модель | REST/WS RBAC и автоматические тесты |
| FR-03 | Realtime-сессия с шагом 1 секунда | WebSocket и simulation loop |
| FR-04 | Семь учебных сценариев | `backend/src/elou_tutor/data/scenarios.json` |
| FR-05 | Восемь отказов инструктора | instructor UI и simulator commands |
| FR-06 | Управление клапанами и уставкой | экран оператора и WebSocket commands |
| FR-07 | Журнал, завершение и ScoreCard | timeline, analyzer, sessions API |
| FR-08 | Прогноз параметров на 15 секунд | ONNX Runtime, вход 30×7, выход 3 |
| FR-09 | Подсказки по локальной базе знаний | TF-IDF retrieval и source metadata |
| FR-10 | Проверка целостности сессии | HMAC-SHA256 и связанный audit log |

## Нефункциональные требования, подтверждённые сейчас

- секрет JWT не короче 32 символов;
- instructor-команды недоступны оператору;
- частота WebSocket-команд ограничена;
- ONNX-инференс и шаг симулятора работают на CPU;
- backend-тесты, Ruff и import-contracts проходят на commit `5e7e5c0`.

## Цели пилота, а не свойства MVP

- калибровка по не менее чем шести месяцам обезличенной телеметрии;
- экспертная валидация физических коэффициентов и порогов;
- подтверждённая нагрузка 50 параллельных сессий;
- SLA, мониторинг, backup/restore и отказоустойчивость;
- интеграция с корпоративными IAM, LMS и АСУ ТП;
- формальная процедура применения результатов в обучении персонала.

Эти пункты нельзя отмечать как выполненные до пилота и протокола испытаний.
