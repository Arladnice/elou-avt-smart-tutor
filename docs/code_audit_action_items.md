## 🔴 Критические проблемы в коде

### 1. Авторизация — бутафория (К8)
**Файл:** `backend/routes/auth.py`
- Токен `"jwt-mock-token-for-..."` — не JWT, нигде не проверяется
- Любой может подключиться к WebSocket как `?role=instructor`
- Разделение ролей — только визуальное (фронтенд)

### 2. Глобальный синглтон ConnectionManager (К1, К3)
**Файл:** `backend/services/connection_manager.py:279`
- `manager = ConnectionManager()` — один экземпляр на весь сервер
- Второй оператор перезапишет сессию первого
- Не масштабируется (противоречит Kubernetes-архитектуре из docs)

### 3. Тесты — обманчивая уверенность (К7)
**Файл:** `backend/tests/test_tutor.py`
- 37/37 проходят, но ни одного теста WebSocket-протокола
- `test_escalation_flag_reset` проверяет `False == False`
- `test_health_endpoint` вызывает функцию напрямую, минуя HTTP

### 4. Секрет в коде (К8)
**Файл:** `backend/utils/security.py:5`
- `SECRET_SALT = "GPNA_IT_CHAMPIONSHIP_2026_SECURITY_SALT"` — хардкод
- Нарушает собственное правило AGENTS.md

### 5. `sys.path.append` в продакшен-коде
**Файлы:** `backend/main.py:13`, `backend/tests/test_tutor.py:10`

### 6. Дублирование сброса сессии (3 копипаста)
**Файл:** `backend/routes/ws.py`
- Строки 22-41 (подключение оператора)
- Строки 159-180 (`change_scenario`)
- Строки 182-201 (`reset`)
- Идентичный код в 3 местах — источник ошибок

## ❗ Главный риск: разрыв «документация vs. код»

| Что написано в docs/ | Что реально в коде |
|---|---|
| JWT Auth Handler + RBAC | Mock-строка `"jwt-mock-token-for-..."`, нигде не проверяется |
| Nginx WAF + Rate Limiter | Ничего, CORS `*` |
| Kubernetes container-per-session | Один Dockerfile, глобальный синглтон |
| PostgreSQL с WAL-g репликацией | SQLite `tutor.db` |
| «Обновление солей при утечке ключей» | Соль захардкожена в `security.py` |
| CI/CD с проверкой контрольных сумм | Нет CI/CD |
