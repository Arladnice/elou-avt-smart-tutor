## Приоритеты до защиты

### P0 — обязательно

1. Трижды пройти успешный сценарий из `docs/demo_scenario.md` на публичном стенде без ручных обходов.
2. Записать резервное видео полного пути: две роли → дефект → действия оператора → ScoreCard → история и контроль целостности.
3. На демонстрационной машине проверить Docker startup, healthcheck и WebSocket после перезапуска.
4. Сверить PPTX с текущими фактами: семь сценариев, восемь дефектов, 157 backend-тестов, синтетические данные ML и отсутствие заявления о промышленной готовности.

### P1 — усиливает оценку

1. Зафиксировать результаты трёх прогонов: время, итоговый балл, отсутствие ошибок console/server logs.
2. Продолжить актуализацию `docs/manual_testing_checklist.md`: вход, роли и начальное состояние уже сверены; остальные ожидаемые значения нужно проверить полным ручным прогоном.
3. Подготовить короткий ответ про масштабирование: PostgreSQL и общий session store появляются на пилоте; сервисы выделяются только по результатам нагрузки.
4. Подготовить честный ответ про ML: обучение на синтетике, ONNX-инференс реальный, метрики не переносятся на промышленную телеметрию без пилотной валидации.

### Не делать до защиты

- не дробить backend на микросервисы;
- не добавлять Kubernetes, Redis или брокер сообщений только ради презентации;
- не расширять набор сценариев и оборудования;
- не заявлять SLA, промышленную готовность или подтверждённый экономический эффект без измерений.
