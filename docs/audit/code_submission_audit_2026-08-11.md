## Findings по приоритету

### P1 — исправить до внешней публикации

1. **Все восемь демо-аккаунтов создаются с одним паролем `Ktk_2026!`.** Пароль находится в исходном коде, включая аккаунт инструктора. На публичном стенде любой читатель репозитория может получить право инъекции отказов, управления сессиями и очистки истории. Начальный пароль нужно брать из обязательной переменной окружения либо создавать одноразовые пароли; для production-профиля автосоздание демо-пользователей следует отключить.

2. **JWT передаётся в query string WebSocket.** URL вида `/ws?...&token=<JWT>` попадает в access-логи Uvicorn, reverse proxy и средства наблюдаемости. Токен действует два часа. Для same-origin развёртывания предпочтительна защищённая HttpOnly/Secure cookie; альтернативно — короткоживущий одноразовый WS-ticket или согласованный WebSocket subprotocol без логирования секрета.

3. **В модели отсутствует отсечка питания ИПМ при уровне нефти ниже 3500 мм.** Требование есть в `docs/equipment_specification.md`, но в модели ЭЛОУ нет состояния высоковольтного питания/ИПМ и соответствующей блокировки. Если ЭЛОУ остаётся агрегированной границей MVP, это нужно явно сказать в защите и не заявлять функцию как реализованную.

4. **Сдаточные презентации не имеют индивидуальных Markdown-дайджестов.** Для `ELOU_AVT_Smart_Tutor.pptx` и `ELOU_AVT_Smart_Tutor_submission.pptx` найден только общий файл контента, но нет однозначной трассировки «бинарный файл → его проверяемый дайджест». По протоколу валидатора это блокер. Отдельный аудит презентации от 11 августа также имеет вердикт «стоп» из-за шаблонных/пустых слайдов и неподтверждённых показателей.

### P2 — желательно закрыть до проверки кода

1. **Холодный пуск К-2 физически противоречив.** Сценарий задаёт `L_2 = 0`, но не задаёт `T_2`; сервер подставляет нормальную температуру куба К-2 `350°C`. В браузере сразу после входа видно пустой куб при 348–350°C одновременно с сообщением «холодное состояние». Нужно либо задать согласованное начальное `T_2`, либо объяснить, что холодным является только атмосферный/печной контур.

2. **Fail-to-Ban допускает внешний lockout и рост БД.** Счётчик привязан только к введённому имени: пять попыток блокируют известный аккаунт на пять минут, а уникальные несуществующие имена создают неограниченное число строк. Нужны ограничения длины, rate limit по источнику, очистка старых записей и политика, не позволяющая анонимному клиенту стабильно блокировать инструктора.

3. **`/api/health/metrics` публично раскрывает служебные показатели.** Endpoint отдаёт размер БД, число WS-соединений, число событий, использование ресурсов и доступность LLM. Health можно оставить публичным, но детальные metrics следует закрыть ролью инструктора либо внутренней сетью.

4. **Quickstart частично неисполняем.** В корневом README указан отсутствующий `npm run typecheck`, а в `backend/README.md` — несуществующая точка входа `backend.main:app`. Актуальные команды: `npx tsc --noEmit` и `python -m uvicorn elou_tutor.api.main:app`.

5. **Сдаточные цифры устарели.** В README и пояснительной записке остаются 156 backend-тестов и 8 отказов; фактически сегодня — 351 backend-тест, 53 frontend-теста, 103 subtests и 9 отказов. В нескольких документах всё ещё встречается DTW, хотя реализация использует LCS.
