# Аудит безопасности backend-контейнера

**Дата проверки:** 4 августа 2026 года  
**Объект:** `backend/Dockerfile`, `docker-compose.yml`, `.github/workflows/deploy.yml`

## Итог

Backend запускается от непривилегированного пользователя `appuser` с фиксированным UID 10001. Запись разрешена только в каталог данных `/app/data`. Обязательные `INTEGRITY_SALT` и `SECRET_KEY` не входят в образ и передаются во время запуска. При отсутствии секрета или длине менее 32 байт приложение прекращает запуск.

## Проверенные меры

| Проверка | Статус | Подтверждение |
|---|---|---|
| Процесс не работает от root | Пройдено | `USER appuser`, UID 10001 |
| У сервисного пользователя нет интерактивного shell | Пройдено | `/usr/sbin/nologin` |
| Домашний каталог не создаётся | Пройдено | `--no-create-home` |
| Каталог БД доступен для записи | Пройдено | `/app/data` принадлежит `appuser` |
| Секреты отсутствуют в Dockerfile и слоях образа | Пройдено | секретные `ENV` удалены |
| Секреты обязательны | Пройдено | backend проверяет наличие и минимальную длину 32 байта |
| Локальный `.env` исключён из Git | Пройдено | compose подключает `backend/.env`, файл игнорируется |
| Deploy использует GitHub Secrets | Пройдено | `INTEGRITY_SALT`, `SECRET_KEY`, `DEPLOY_PASSWORD` читаются из `secrets.*` |
| API не публикуется напрямую наружу | Пройдено | порт привязан к `127.0.0.1:8000` |
| Состояние БД вынесено из контейнера | Пройдено | named volume `tutor_data:/app/data` |

## Рекомендации для промышленного контура

1. Перейти с SSH-пароля на отдельный deploy-ключ и непривилегированного пользователя хоста.
2. Закрепить отпечаток SSH-хоста через `DEPLOY_KNOWN_HOSTS` вместо `StrictHostKeyChecking=accept-new`.
3. Для целевого оркестратора использовать файловые secrets с коротким временем жизни; переменные окружения допустимы для текущего MVP, но видны процессу и администратору Docker.
4. Добавить read-only root filesystem и временный `tmpfs`, когда будет подтверждено, что все runtime-записи ограничены `/app/data`.

## Вердикт

Для конкурсного MVP конфигурация контейнера приемлема: root не используется, секреты не запекаются в образ, значения по умолчанию отсутствуют, внешний доступ к backend ограничен reverse proxy. Оставшиеся рекомендации относятся к промышленному hardening и не блокируют демонстрацию.
