## 1. Зачем нужна IT-инфраструктура?

IT-инфраструктура — это невидимый фундамент любого корпоративного решения. Она включает три слоя:

| Слой | Что входит |
|---|---|
| **Инженерная инфраструктура** (нижний) | Электропитание, кабельные сети, охлаждение, пожаротушение, контроль доступа |
| **Сетевая инфраструктура** (средний) | Каналы связи, коммутаторы LAN, беспроводная сеть, маршрутизаторы |
| **Вычислительная инфраструктура** (верхний) | Серверы, СХД, системы виртуализации |

**Ключевые требования:** вычислительные ресурсы, место для хранения данных, каналы передачи, электропитание и охлаждение.

## 2. Центры обработки данных (ЦОД): уровни Tier

ЦОДы делятся на четыре уровня надёжности (Tier):

| Уровень | Доступность | Применение |
|---|---|---|
| **Tier-1** | Минимальная | Для некритичных систем, дешевле всего |
| **Tier-2** | Базовое резервирование | Средний бизнес |
| **Tier-3** | Основной для России | Высокая доступность, допускается плановое обслуживание |
| **Tier-4** | Максимальная (24×7×365) | Очень редко в России, максимально дорого |

> **Вывод:** Система 24×7 (как ЭЛОУ-АВТ Smart Tutor) должна размещаться на Tier-3 и выше.

**Инженерные требования к ЦОД:**
- Охраняемое помещение с контролем доступа
- Газовое/аэрозольное пожаротушение
- Система горячего/холодного коридора для охлаждения
- Защитное заземление и ИБП (UPS)
- Дизель-генераторы для аварийного питания
- Два независимых ввода электропитания (для Tier-3/4)
- Дублирование PDU (Power Distribution Unit) в каждой стойке

## 3. Серверы: физические и виртуальные

**Сервер** — устройство или экземпляр ПО, работающий без участия человека в режиме 24×7.

### 3.1 Основные характеристики сервера

| Компонент | Описание |
|---|---|
| **CPU (ЦПУ)** | Количество ядер × тактовая частота. Серверные: Intel Xeon Scalable (4-6 gen), AMD EPYC |
| **RAM (ОЗУ)** | До 16 модулей на 1 процессор. Несбалансированная конфигурация → 20% от максимума |
| **Дисковая подсистема** | HDD или SSD. Характеристика: IOPS (с учётом профиля нагрузки) |
| **PCI-E** | Внутренняя шина. Поколение + число линий (x8, x16) определяют пропускную способность |

### 3.2 CPU vs GPU

| Параметр | CPU | GPU |
|---|---|---|
| Ядра | Мало, высокопроизводительные | Тысячи простых ядер |
| Задачи | Прикладные системы, ОС, сложная логика | ML/AI, параллельные вычисления |
| Режим | Последовательный + параллельный | Массово-параллельный |
| Примеры | Intel Xeon, AMD EPYC | NVIDIA A100, H100, GeForce RTX |

**Важно для ML:** GPU имеют специализированную HBM-память (высокая пропускная способность). Объём GPU RAM ≥ размер модели в параметрах × точность хранения + запас для инференса.

### 3.3 Дисковая подсистема

| Тип | Преимущества | Применение |
|---|---|---|
| **HDD** | Долговременное хранение, дешевле, стабильная производительность на больших блоках | Архивы, видео, «холодные» данные |
| **SSD** | Высокий IOPS на малых блоках, быстро | БД, виртуализация, «горячие» данные |

**RAID-уровни:**
- **RAID-1** — зеркалирование (2 диска, полное дублирование)
- **RAID-5** — одинарная чётность (выход из строя 1 диска) — **самый популярный**
- **RAID-6** — двойная чётность (выход из строя 2 дисков)

**Hot-plug:** Все критичные компоненты (диски, БП, вентиляторы) в серверах заменяются без остановки.

## 4. Системы хранения данных (СХД)

**СХД (Storage Area Network / SAN)** — внешние дисковые массивы для централизованного хранения данных нескольких серверов.

### 4.1 Типы СХД

| Тип | Описание |
|---|---|
| **Блочный доступ (SAN)** | FC или iSCSI, «сырые» блоки, высокая производительность |
| **Файловый доступ (NAS)** | Сетевые файловые хранилища (SMB, NFS) |
| **Программно-определяемые (SDS)** | Виртуализация локальных дисков серверов в единый пул (Ceph, VSAN) |
| **Объектные хранилища** | API-доступ, метаданные, гибкая иерархия (S3-совместимые: MinIO, Ceph RGW) |

### 4.2 Архитектура СХД

- **Двухконтроллерная** (обязательно для отказоустойчивости)
- **Режим Active/Passive** — один контроллер активен, переключение при отказе (пауза ~секунды)
- **Режим Active/Active** — оба контроллера одновременно обрабатывают I/O (нет задержки при отказе)

### 4.3 Многоуровневое хранение (Multi-Tiering)

```
Tier-1 (SSD NVMe) — горячие данные — дорого, быстро
Tier-2 (SSD SATA) — тёплые данные
Tier-3 (HDD SAS)  — холодные данные — дешево, медленнее
```

## 5. Виртуализация

**Виртуализация** — абстракция вычислительных, сетевых и дисковых ресурсов от физического железа.

### 5.1 Преимущества

| Преимущество | Описание |
|---|---|
| **Контроль** | Каждой ВМ — ровно столько ресурсов, сколько нужно |
| **Гибкость** | Изменение ресурсов на лету без остановки ВМ |
| **Изоляция** | Сбой у соседней ВМ не влияет на вашу |
| **Экономия** | Платите только за фактически используемые ресурсы |

### 5.2 Недостатки

- **Компетенции:** Требуются квалифицированные специалисты (CapEx/OpEx)
- **Производительность:** ~10–30% накладных расходов vs bare-metal
- **Безопасность:** Взлом гипервизора/хоста → компрометация всех ВМ

> **Правило:** Критичные нагрузки (СУБД, ML-инференс с жёсткими задержками) — развёртывать на bare-metal, а не в ВМ.

### 5.3 Гипервизоры

| Тип | Описание | Примеры |
|---|---|---|
| **Type 1 (Bare Metal)** | Гипервизор = ОС, напрямую на железо | VMware ESXi, KVM, Hyper-V Server |
| **Type 2 (Hosted)** | Гипервизор поверх ОС | VirtualBox, VMware Workstation |

**Кластеры гипервизоров:** Объединяют несколько физических хостов в единый пул для HA (высокой доступности), Live Migration (перенос ВМ без остановки) и балансировки нагрузки.

### 5.4 Программно-определяемые решения

- **SDN (Software Defined Network)** — виртуальные коммутаторы (vSwitch, DvSwitch в VMware), управление сетью из одной точки, VLAN без физических свитчей
- **SDS (Software Defined Storage)** — объединение локальных дисков разных хостов в единый отказоустойчивый пул

### 5.5 Конвергентные и гиперконвергентные системы (HCI)

```
Традиционная: сервер ←→ внешняя СХД ←→ коммутаторы FC
HCI (Hyper-Converged): один узел = CPU + RAM + SSD/HDD + сеть
                        Всё управляется единым ПО (vSAN, Nutanix, Аvirt)
```

## 6. Облачные модели развёртывания

### 6.1 Модели сервисов

| Модель | Кто управляет железом | Кто управляет ОС | Кто управляет приложением |
|---|---|---|---|
| **IaaS** | Провайдер | Вы | Вы |
| **PaaS** | Провайдер | Провайдер | Вы |
| **SaaS** | Провайдер | Провайдер | Провайдер |

### 6.2 Типы облаков

- **Публичное** — AWS, Azure, Яндекс.Облако, VK Cloud
- **Приватное (on-premise)** — своё оборудование в собственном или арендованном ЦОД
- **Гибридное** — часть on-premise, часть в публичном облаке

> **Для ЭЛОУ-АВТ Smart Tutor:** Рекомендуется **on-premise** (или частное облако на предприятии), т.к. данные АСУ ТП не должны покидать периметр ИБ. WebSocket-задержка при работе через публичное облако может не соответствовать требованиям реального времени.

## 7. Безопасность виртуальной инфраструктуры

### 7.1 Векторы атак

1. **Кража данных** (с 2022 года — приоритет злоумышленников)
2. **Шифровальщики-вымогатели** (ransomware)
3. **Скрытое использование ресурсов** (криптомайнинг)
4. **Lateral movement** — взлом одной ВМ → атака на соседние

**Точки атаки:**
- Гипервизор (уязвимости ESXi/KVM)
- API управления (vCenter, oVirt API)
- Шаблоны ВМ
- Общие ресурсы (файловые шары)
- **Социальная инженерия** (Кевин Митник — самый распространённый вектор)

### 7.2 Защита

| Уровень | Меры |
|---|---|
| **Гипервизор** | Обновления, двухфакторная аутентификация (SSO), изоляция управляющей сети |
| **Виртуальные машины** | Микросегментация сети, шифрование дисков, запрет избыточного общего доступа |
| **Мониторинг** | SIEM-системы, IDS/EDR, антивирус |
| **Резервное копирование** | **Правило 3-2-1:** 3 копии, на 2 разных носителях, 1 — вне площадки |

## 8. Как выбрать GPU-сервер для ML

### 8.1 Алгоритм выбора

1. **Бизнес-требования:** число пользователей, допустимая задержка, тип задачи (инференс vs обучение)
2. **Тип нагрузки:** классификация/числовой ответ → CPU; генерация длинных текстов, обучение → GPU
3. **Объём памяти GPU:** `размер_модели_параметры × точность + запас_инференс`
4. **Тип памяти:** GDDR5/6 (GeForce/RTX) vs HBM2e/HBM3 (A100/H100) — HBM быстрее
5. **Балансировка:** RAM ≥ 2×VRAM; CPU не должен быть узким местом

### 8.2 Линейки NVIDIA

| Линейка | Охлаждение | Применение |
|---|---|---|
| **GeForce RTX** | Активное (вентиляторы) | Разработка, тесты |
| **RTX Professional** | Активное / пассивное (Server Edition) | Профессиональные задачи |
| **Data Center (A/H/B series)** | Пассивное, DLC | Продакшн ML/AI |

**Форм-факторы:**
- **PCIe** — стандартный слот, одиночное или парное соединение через NVLink-мост
- **SXM** — высокопроизводительный, NVLink + NVSwitch (связь всех GPU между собой), только в профессиональных серверах

**Охлаждение:**
- Воздушное: горячий/холодный коридор в стойке
- **DLC (Direct Liquid Cooling)** — жидкостное охлаждение, позволяет плотнее упаковать GPU в сервер
