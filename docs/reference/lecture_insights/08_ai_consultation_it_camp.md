## 🎯 Ключевые тезисы консультации

### 1. Архитектура тренажера — 3 уровня зрелости

> *«В тренажёре в целом есть три уровня: первый — это физика (мат-модели, гидродинамика, теплообмен), её мы НЕ связываем с ИИ. Второй — дефекты и уставки оборудования. И Уровень 3 — это непосредственно зона искусственного интеллекта: анализ действий оператора, определение ошибок, причины и рекомендации.»*

```
+-----------------------------------------------------------------------------------+
| УРОВЕНЬ 3: ЗОНА ИИСКУССТВЕННОГО ИНТЕЛЛЕКТА                                        |
| • Оценка компетенций и действий обучаемого оператора                              |
| • Динамическая классификация и временная локализация ошибок                      |
| • Объяснение причин и рекомендация обучающих материалов (RAG без галлюцинаций)     |
| • Упреждающий прогноз рисков до ошибки (Lead Time)                                |
| • Адаптивный траекторный сценарий повторного обучения                             |
+-----------------------------------------------------------------------------------+
                                         ↑
+-----------------------------------------------------------------------------------+
| УРОВЕНЬ 2: ДЕФЕКТЫ И БЛОКИРОВКИ ПАЗ (Логика и уставки)                            |
| • Пороговые уставки техрегламента (T, P, L)                                      |
| • Формализация типовых отказов оборудования (прогар, отказ насосов, заклинивание) |
+-----------------------------------------------------------------------------------+
                                         ↑
+-----------------------------------------------------------------------------------+
| УРОВЕНЬ 1: ФИЗИКО-ХИМИЧЕСКАЯ МОДЕЛЬ (НЕ ИИ)                                       |
| • Дифференциальные уравнения физико-химических процессов (simulator)               |
+-----------------------------------------------------------------------------------+
```

### 2. Чёткая граница: что ЯВЛЯЕТСЯ ИИ, а что НЕ ЯВЛЯЕТСЯ ИИ

> *«Очень важно не путать ИИ и физику или математические модели. Не создавайте "фасад", который красиво выглядит, но работает только на простых правилах.»*

| Компонент / Задача | Категория | Почему не ИИ / Зачем ИИ |
|---|---|---|
| Расчёт физики установки | ❌ НЕ ИИ | Дифференциальные уравнения и математическая модель процесса |
| Проверка порогов уставок ($T > 380^\circ\text{C}$) | ❌ НЕ ИИ | Детерминистические пороговые правила (If/Else) |
| Сравнение со статическим эталоном | ❌ НЕ ИИ | Поэлементное сравнение векторов (Baseline) |
| 3D-визуализация / SCADA UI | ❌ НЕ ИИ | Графический интерфейс и дашборды для человека |
| Классификация типов ошибок оператора | ✅ **ИИ** | Идентификация сложных патернов отклонений (DTW/ML) |
| Временная локализация ошибки | ✅ **ИИ** | Точное определение момента и шага возникновения нарушения |
| RAG-объяснение причин по регламентам | ✅ **ИИ** | Привязка к базе знаний без галлюцинаций (VectorStore) |
| Упреждающий прогноз риска до ошибки | ✅ **ИИ** | Прогнозирование временных рядов телеметрии (RiskLSTM) |
| Адаптивный сценарий повторного обучения | ✅ **ИИ** | Динамический выбор курса и сценария дообучения (Tutor) |

### 3. Ступенчатая оценка ИИ-модуля (0.10 от общей оценки)

> *«Баллы идут от самого простого подхода к наиболее сложному. Показывайте на демо ровно то, что заявляете в презентации.»*

| Балл | Что необходимо реализовать | Архитектурное решение в проекте |
|---|---|---|
| **1 балл** | Фиксация действий + сравнение с эталонным сценарием | Запись журнала событий (`AlarmLog`) + baseline порогов |
| **2 балла** | Идентификация и классификация типовых ошибок | Классификатор отклонений действий по категориям ТБ/ИБ |
| **3 балла** | Классификация + **локализация во времени** + **причинно-следственные связи** | Алгоритм DTW (`ErrorAnalyzer`), определяющий точный шаг ошибки |
| **4 балла** | Всё выше + **подробная обратная связь из техрегламентов** | RAG-база знаний (`VectorStore`) без галлюцинаций (`min_score = 0.08`) |
| **5 баллов** | Всё выше + **прогноз риска ДО ошибки** + **адаптивный сценарий дообучения** | Нейросеть `RiskLSTM` (Lead Time 15с) + Персональный сценарий дообучения (`ScoreCard`) |

### 4. Юридические риски, ИБ и импортонезависимость

> *«Я не рекомендую использовать модели от OpenAI, Google и т.д., потому что это подвергает вашу систему и компанию юридическим и санкционным рискам. Используйте локальные инференс-мощности и открытые веса.»*

- **Запрет проприетарных зарубежных API:** Запрещено использовать ChatGPT / Claude API.
- **Локальный стек:** Инференс через ONNX Runtime (`ai_core/model.onnx`) и локальную LLM (LM Studio / Ollama / GPN internal stack).
- **Защита от галлюцинаций (RAG Grounding):** LLM обязана опираться на вектора базы знаний (`knowledge_base/`). При отсутствии ответа в базе — вывод предупреждения: *"Информация не найдена"*.

### 5. Построение взаимодействия с пользователем (Инструктор / Оператор / Менеджмент)

- **АРМ Оператора:** Замкнутый контур (физика $\leftrightarrow$ SCADA $\leftrightarrow$ ИИ-подсказки в предписывающем формате).
- **АРМ Инструктора:** Полный контроль тренировки, инъекция дефектов оборудования, прием фидбека по алармам ИИ (Closed-loop feedback ✅/❌).
- **Дашборд Руководителя:** Отчеты квалификации (`ScoreCard`), статистика ошибок, динамика дообучения.
