# Data card: synthetic telemetry v2

## Происхождение

Датасет создаётся `ml_training/data_generator.py` из физического симулятора ЭЛОУ-АВТ. Реальная телеметрия в исходных материалах кейса не предоставлена, поэтому данные предназначены для проверки учебного ML-контура, а не для производственного внедрения.

## Версия

| Поле | Значение |
|---|---|
| Dataset version | `2026-08-08-v2` |
| Generator version | `2.0` |
| Seed | `42` |
| Объём | 100 000 строк, 696 сессий |
| SHA-256 | `b7c059f397d6e6ea1c002f80f8e951acb57b433f328e9c5b9e8adda809b46cdc` |
| Split | 70% train / 15% validation / 15% test, строго по `session_id` |

Полные метаданные хранятся рядом с CSV: `ml_training/data/telemetry_dataset.csv.metadata.json`.

## Поля

В каждой записи есть идентификатор сессии, время, состояния клапанов V-1/V-2/V-3, уставка T-1, телеметрия T-1/P-1/L-1, признаки дефектов, расчётный риск, статус, тип сценария и версия датасета.

## Сценарии

Генератор формирует штатный режим, пуск и шесть типов отказов: перегрев змеевика, отказ насоса, заклинивание клапана, отказ электропитания, отказ воздуха КИПиА и срыв подачи пара. Число сессий по каждому сценарию фиксируется в metadata-файле.

## Ограничения и контроль качества

- Все сессии генерируются с фиксированным seed; повторный запуск воспроизводим для одинаковой версии кода.
- Соседние окна одной сессии не пересекают train/validation/test.
- Синтетика наследует упрощения физического симулятора и не заменяет реальную телеметрию.
- Перед пилотом требуется экспертная проверка технологических порогов, покрытие редких дефектов и валидация на архивных данных.
